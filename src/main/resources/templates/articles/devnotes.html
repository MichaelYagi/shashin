Multi-select media editing

  • See Search module as an example
  • You must add tag <div th:replace="~{fragments/metadatabatchmodal :: metadatabatchmodal(${recognitionLabels},${allAlbumList})}"></div> in order to access the multi-select modal dialog
  • For each metadata, you should add hidden inputs to show proper headings in the modal dialog:
    • <input type="hidden" th:name="'filename'+${metadata.id}" th:id="'filename'+${metadata.id}" th:value="${metadata.fileName}">
    • <input type="hidden" th:name="'thumbnailCentered'+${metadata.id}" th:id="'thumbnailCentered'+${metadata.id}" th:value="${metadata.thumbnailUrlCentered}">
  • In the controller, it must extend BaseController and in the action, call getAllAttributeData(model) in order to prefill album and people dropdowns

Front end debugging

Apart from standard IDE debuggers, convenience functions to look at console outputs can be enabled.

Place shashin.printMessageToConsole(<message>,{<options>}) in JS code where you'd like to see console outputs. Options are a hash map of allowable options.

tag - tags outputs to be used as a filter.
type - allows for different console types to be used, shashin.consoleTypes.error, shashin.consoleTypes.info, shashin.consoleTypes.log, or shashin.consoleTypes.warn.

Typing shashin.enableDebug({<options>}) in the browser console will output console log messages placed in the app. There are various options you can pass.

tags - an array of tags to filter on. Default is "all", to output all tagged messages.
filter - an array of console types to filter on. Default is for all console types to be shown.
showTrace - if set to true, shows the stack trace for the output. Default is false.
writeLog - if set to true, makes network requests to the backend to write console outputs to the app logs. Default is false.

Typing shashin.disableDebug() in the browser console prevents any output from the app to be shown in the console window.
