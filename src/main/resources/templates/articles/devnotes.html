i18n

Internationalization files can be found in the resource folder, where messages.properties contain the English (default) translations. The intention being more will be added in the future, with file format messages_xx.properties where xx is the 2 letter language code.

Javascript output will also need to be translated. This will be tracked as globals sourced from the translation files in src/main/resources/templates/fragments/translations.html. They should map to entries in messages.properties.

Access in controllers: Make sure to autowire MessageSources

@Autowired
var messageSource: MessageSource? = null
In controller parameters, add locale: Locale, then in the code, get the translation using the translation path messageSource.getMessage("path.to.translation.from.messages.properties", null, locale)

Access in javascript: Call shashin.getTranslatedValue("path.to.translation")

Access in thymeleaf: Example: #messages.msg('path.to.translation') or #{'path.to.translation'}

Front end debugging

Apart from standard IDE debuggers, convenience functions to look at console outputs can be enabled.

Print console messages

Place shashin.printMessageToConsole(<message>,{<options>}) in JS code where you'd like to see console outputs. Options are a hash map of allowable options.

tag - tags messages to be used as a filter.
consoleType - allows for different console types to be used for a message, shashin.consoleTypes.error, shashin.consoleTypes.info, shashin.consoleTypes.log, or shashin.consoleTypes.warn. Default is shashin.consoleTypes.info

Example:
shashin.printMessageToConsole("test",{
    tag: "testcode",
    consoleType: shashin.consoleTypes.error
});

Enable debug messages in the console

Typing shashin.enableDebug({<options>}) in the browser console will output console log messages placed in the app. There are various options you can pass.

tags - an array of tags to filter on. Tag value "all" shows all logs without tag filtering. Default is for all tags to be shown.
consoleTypes - an array of console types to filter on. Default is for all console types to be shown.
showTrace - if set to true, shows the stack trace for the output. Default is false.
writeLog - if set to true, makes network requests to the backend to write console outputs to the app logs. Default is false.

Disable debug messages in the console

Typing shashin.disableDebug() in the browser console prevents any output from the app to be shown in the console window.

Toast messages

Pop-up messages can be used to notify users. There are 9 quadrants you can see pop-ups.

Show toast messages

Place shashin.showToastMessage(<title>, <message>, {<options>}) in JS code. Options are a hash map of allowable options.

icon - use Bootstrap Icons. eg. bi-info-circle. Default is empty.
iconColor - allows for different CSS colors for the icon eg. "red" or "#FF0000". Default "lightgray"
headerSubtext - Text that sits beside the title in smaller print. Default is an empty string.
autohide - Flag whether the toast will automatically hide. If false, user will be forced to close the notification. Default is true.
delay - Time in which toast message will close in milliseconds. This option will be ignored if autohide is set to true. Default is 5000 ms.
placement - Determines the placement of the toast message. Default is bottom middle. Options are:
    shashin.toast.placement.default
    shashin.toast.placement.top.left
    shashin.toast.placement.top.center
    shashin.toast.placement.top.right
    shashin.toast.placement.middle.left
    shashin.toast.placement.middle.center
    shashin.toast.placement.middle.right
    shashin.toast.placement.bottom.left
    shashin.toast.placement.bottom.center
    shashin.toast.placement.bottom.right
borderColor - The border color of the toast notification. Default is secondary. Options are: primary, secondary, success, danger, warning, info, light, dark, white
tag - A string that identifies and labels the toast. Default is empty.
refreshTag - If tag is defined, overwrites the tag content with any updated content. Default is empty.
closeButton - Hide close button if false. Default is true.

Example:
shashin.showToastMessage("test title","test message"{
    headerSubtext: "Keep it short!",
    icon: "bi-exclamation-triangle",
    icon: "#FF0000",
    delay: 6500,
    placement: shashin.toast.placement.top.left,
    tag: "testcode",
    refreshTag: true
});

Close toast messages

Place shashin.closeToastMessages() in JS code. Options are a hash map of allowable options.

tag - Target specific tag to close.
tags - Array of tags to close.
placement - Target specific placement to close. Options are:
    shashin.toast.placement.default
    shashin.toast.placement.top.left
    shashin.toast.placement.top.center
    shashin.toast.placement.top.right
    shashin.toast.placement.middle.left
    shashin.toast.placement.middle.center
    shashin.toast.placement.middle.right
    shashin.toast.placement.bottom.left
    shashin.toast.placement.bottom.center
    shashin.toast.placement.bottom.right
placements - Targets multiple placements to close.
hide - Flag to remove or hide toast message. If set to true, will only hide the element, else it will remove the element from the DOM. Default is false.

Examples:
// Hides toast messages tagged 'testcode' or 'anothertag' targeting bottom center toast messages
shashin.closeToastMessages({
    tags: ["testcode", "anothertag"],
    placement: shashin.toast.placement.bottom.center,
    hide: true
});

// Removes all toast messages
shashin.closeToastMessages();
